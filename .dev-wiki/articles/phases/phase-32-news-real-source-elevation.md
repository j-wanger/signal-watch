## Why it extends the vision (not a bolt-on)

- Phase 31 proved the muscle (news → grounded entity + red-flag extraction → fuzzy-match → exposure → human gate) but shipped it as a staged slide show — exactly the Phase-27 corpus failure (RESULT not PROCESS). This phase raises the news stream to the corpus's already-shipped bar; the same complaint, the same fix, applied to the newer artifact.
- The REAL source makes the bridge honestly more compelling than fictional-vs-fictional: OFAC designations / DOJ ML indictments are precisely what real adverse-media screening hits on, and they carry recognizable real cases. REAL adverse-media entity × SYNTHETIC book is the honest demo.
- aml-wiki grounding stays load-bearing: entity-resolution fragmentation + the >90% false-positive wall = the fuzzy-match-then-human-disposition beat ([[wiki:adverse-media-screening]]); ~80% of investigative intelligence is in unstructured text ([[wiki:entity-resolution-and-network-analytics]]).
- Compliance basis is NOT a non-negotiable change — it is the EXISTING US-federal verbatim basis (17 U.S.C. §105, extended FinCEN→US-federal in Phase 21 for OFAC) applied to a NEW artifact (the news stream), exactly how OFAC extended it. The book stays synthetic; the always-on illustrative badge stays.

## Architecture

Reuses the Phase-31 news-stream + the corpus's presentation discipline:
- Build-time, committed: `data/news/articles/*.md` — REAL US-federal gov-enforcement docs (DOJ/OFAC/Treasury-FinCEN/SEC), acquired build-time via WebSearch/WebFetch → committed verbatim with a provenance header (source URL + public-domain basis), the EXACT corpus authoring discipline → `data/news/derived/*.json` (named `entities` with name + location + age + profession [each QUOTE-GROUNDED in the article; DROP any attribute that can't ground — DOJ releases routinely carry "X, 45, of Miami, a licensed attorney…" so the attributes ARE groundable] + grounded red-flag `flag` + `red_flag` translation + `typology`) + `data/news/book.json` (the SYNTHETIC counterparty book reseeded so the matcher hits the REAL entities — exact + near-match + a common-name false-positive trap + clean rows). Validated at the BUILD BOUNDARY (`validate_news_data` extended for entity attributes, a LOCAL `_news_normalize` so build.py STILL never imports the authoring layer) — the grounding core `derive_signals.py` stays BYTE-FROZEN.
- Runtime (offline, single file): the pure client-side fuzzy matcher (normalize → token-sort → Jaro-Winkler, REAL scores, thresholded) stays; the presentation is rebuilt — the streaming Read render (caret + scroll-follow, each red-flag phrase highlights as the read reaches it, typology + entity cards reveal alongside, counts up from 0) ported from the corpus `renderArticle`, and a VISIBLE SCAN PROCESS on Screen (each book row scored in a sweep, ranked into exposure, threshold line, near-matches surfaced, the common-name trap flagged) replacing the jump-cut.
- Arc (`news.html` → `dist/news/`): Select → streaming Read (red-flags highlighted + typology + entity cards) → scan-PROCESS Screen (fuzzy-match sweep, ranked exposure, near-match surfaced) → Disposition (human gate; dismiss the trap) → Close (confirmed exposure). Full corpus dossier theme; illustrative badge always on.

- The client/counterparty book MUST be synthetic (non-negotiable #4 — no real customer data, ever). The articles are REAL US-federal gov-enforcement docs (public domain, 17 U.S.C. §105) — the corpus's existing verbatim basis applied to a new artifact, NOT a non-negotiable change.

The always-on "Illustrative data & outputs" badge stays (the scenario/book/exposure is illustrative, the source articles real — the corpus's own real-source-under-illustrative-badge model); source attribution rendered like the corpus.
