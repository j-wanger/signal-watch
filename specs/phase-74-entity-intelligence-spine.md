# Spec: Phase 74 — The Persistent Entity Intelligence Spine (consumer + standards + sibling handoffs)

## Objective
Stand up a companion-only **persistent entity intelligence spine** that ties records to the same counterparty over time, presents each entity's resolved context (network, source of funds, prior dispositions) consistently on every surfacing, and accumulates prior decisions on the entity — proven by a thin deterministic slice in the live investigator workbench. Author the cross-repo **standards/schemas** that govern resolution, identity grading, and confidence provenance here, and hand off **emission briefs** to the sibling repos.

## Context
The decisioning lever this program is chasing — separating two cases that fire the SAME grounded signals but deserve OPPOSITE outcomes (the committed Northgate-files / Lakeshore-clears pair in `data/casefile/case.json`) — rests on evidence that lives in the entity's network and source of funds, not the transaction stream. That evidence must persist on a resolved entity, or every alert re-gathers it cold.

Code-verified starting state (2026-06-25): `scripts/news_store.py` is a DuckDB companion store with the right bones (anchor + per-row provenance + conflicting-values-both-kept + reversible `prune` + fuzzy-merge deferred) but keys identity on the exact-normalized **name** and is walled into the M8 news pillar (`set_disposition` hard-wired to news escalation vocabulary; no other script imports it). `scripts/serve_workbench.py` reads per-case committed JSON only — zero entity persistence; `resolution_edges`/`related_parties` are authored per case. `scripts/evidence_requirements.py` `evaluate_sufficiency()` is pure-boolean and the file/determination bar is byte-frozen (the "A1 guard", asserted by its `--selftest`). The sibling synthetic-data repo (`/Users/jwang/aml-substrate`) is Parquet-only; it assigns ground-truth `party_id` at generation and holds hidden ground-truth identity clusters in `true_entities.parquet`, with a ground-truth-blind `resolver.py`; counterparties on transaction legs currently emit only a name + a synthetic ref (the identifier hooks exist on the party model but are inert). No medallion / DuckLake / Splink / Kuzu exists anywhere.

This phase is the thin deterministic slice + the standards + the briefs. The full medallion/DuckLake/Splink/Kuzu/probabilistic-ER stack is the *target* architecture for the substrate/program pillar and is explicitly out of scope.

## Scope
### In scope
- A **pillar-neutral persistent entity spine** generalized from `news_store.py`'s observation/provenance/conflict/reversible machinery: observations (presented attributes with provenance) + an append-only **resolution-link layer** (observation → bitemporal link → `persistent_entity`) + the accumulating entity record (resolved best-view + entity-resident facts + prior dispositions and their grounding chains).
- **Deterministic linkage only**, per the casefile's identifier grammar: exact-normalized email/phone/strong-identifier match = a link; address = weak; **name-only = reject** (the `E-CALDERON` exclusion is the spec). Exact-name-equality is demoted from "the entity key" to one deterministic rule feeding the link layer.
- Wiring `serve_workbench.py` to **read** entity-resident facts + prior dispositions from the spine, proven on the matched Northgate/Lakeshore pair, plus a re-surfacing **"memory" demo**: the second time an entity surfaces, its prior disposition + grounding chain arrive pre-assembled and the gather loop short-circuits (time-to-sufficiency collapse — the honest, label-free proof of the lever).
- **Confidence carried as an ordinal identity GRADE** all the way from resolution-link → entity fact → the analyst-visible view, on a **separate read path** that never alters the byte-frozen filing engine.
- A **stale-prior guard**: a reused prior carries the resolution-version it was decided under; if the entity identity changed since, it is surfaced as "re-decision required", never trusted silently. A **split (un-merge)** cascade-invalidates dispositions whose grounding crossed the retracted edge.
- **Standards/schemas authored here** (committed docs/schema files): (a) the resolution-link schema (bitemporal valid-time + decision-time; append-only supersede-not-overwrite; reversible merge/un-merge); (b) the strong/weak/reject ordinal identifier grammar with named per-grade criteria + a `basis[]`; (c) the confidence-as-provenance contract; (d) the `true_entities` resolution-correctness SCORER contract (synthetic clusters validate the resolver; production has no ground truth → human-adjudication-rate, not accuracy).
- **Three handoff briefs** (docs, sibling-executed — the Phase-55–58/66 pattern): aml-substrate graded-counterparty-identifiers; aml-substrate exogenous-disposition-label-decoupled-from-the-sufficiency-rule; aml-casework consume-confidence-graded-resolution.

### Out of scope
- Probabilistic / fuzzy resolution (Splink), the merge-adjudication Class-J console, and graph analytics (Kuzu) — DEFERRED as governed enhancements; named in the standards as the next layer, not built.
- The medallion (bronze/silver/gold), DuckLake, and any 2D (resolution-version × data-snapshot) time-travel.
- Any change to the offline ship artifacts, the 8 dists, or the filing/determination threshold.
- Executing the sibling briefs (they are emitted here, implemented in their own repos).

## Approach
Generalize the proven `news_store` machinery rather than greenfielding: keep observations-with-provenance and conflicting-values-both-kept; add the one missing layer (append-only, bitemporal resolution links) so identity becomes a *derived, revisable, graded* assertion instead of a name key. Keep persistence and resolution separate: deterministic linkage now, the probabilistic/graph layers later behind the same link contract. Treat every merge as a reversible, audited belief. Carry uncertainty as an ordinal grade that **fails closed** (unknown/missing grade → weakest → excluded from any decision input), because a frozen *boolean* filing engine cannot express "but the identity link is weak" — so low-grade inherited evidence must be **excluded, not down-weighted**. The grade is **deterministic linkage-strength** derived from the identifier grammar (strong = exact email/phone/identifier match, weak = address, reject = name-only), NOT a probabilistic match score — a model-emitted confidence is a fabricated-shaped number, and `news_store` keeps confidence reserved by explicit decision; a probabilistic score is admissible only when measured against `true_entities` (the scorer contract). Each filing decision emits an **inspectable manifest** of evidence atoms admitted vs. quarantined-by-low-grade, so the file/clear is auditable down to the link that supplied each atom. Priors and accumulated history are **analyst-visible provenance only**; the filing engine must never read them, or the store becomes a self-confirming loop ("previously cleared" → clears again). The synthetic ground-truth firewall is enforced at the schema boundary, not by convention.

### Domain Research Questions
- What is the minimal ordinal identity-grade vocabulary that the casefile's strong/weak/reject distinctions, the news `PROPERTY_KINDS`, and the substrate's identifier set all map onto without lossy collapse — and which grade must a missing/unknown value fail closed to?
- Bitemporal modeling: do production-disposition reuse (decision-time frozen) and analytics impact-assessment (current-resolution recompute) each need only a 1D lens, and what is the smallest column set (valid-time, decision-time, resolution-version) that serves both without a cross-product?
- For the stale-prior guard, what is the cheapest signal that an entity's identity "changed since a prior was decided" — a resolution-version counter on the anchor, an edge-set hash, or a supersession marker — given the deterministic-only link set?

## Constraints (CRITICAL)
- **A low-confidence link must not flip a frozen-threshold decision.** The boolean filing engine cannot express identity uncertainty, so any evidence atom inherited across a link below a declared grade is **excluded** from the decision inputs (not down-weighted). — Guard: the filing engine consumes a grade-gated view; a per-decision manifest lists atoms admitted vs. quarantined-by-low-grade; `evidence_requirements.py` byte-identical (its `--selftest` passes unchanged).
- **Accumulated dispositions must not become a self-confirming signal.** — Guard: priors enter only as analyst-visible provenance; a regression test asserts that injecting a prior `cleared` disposition produces **zero change** in the file/clear output for a fixed evidence set.
- **A discovered-wrong merge must not leave its dispositions standing.** — Guard: links are reversible transactions; a split cascade-marks every disposition whose grounding crossed the retracted edge as "re-decision required" (audit trail preserved, never deleted).
- **The synthetic ground-truth cluster id must never reach the resolver.** — Guard: the resolver-input schema physically omits any cluster field; a contract test fails if a resolver-input field is 1:1 correlated with cluster identity; the cluster id lives only in the scorer's evaluation-only channel.
- **Resolver accuracy is synthetic-only and must never read as production-trustworthy.** — Guard: every resolver-quality number carries the "measured on synthetic clusters; production has no ground truth" qualifier; the only production-reportable signals are confidence-grade distribution and human-adjudication rate.
- **Confidence must not collapse to a bare float across repos.** — Guard: the standard defines an ordinal grade with named criteria + `basis[]`; the gate keys on the grade; a missing/unrecognized grade fails closed to weakest.
- **Companion-only firewall.** — Guard: `build.py` imports neither the spine nor its schema module; `python3 scripts/build.py --check all` is 8/8 byte-identical; the spine binds 127.0.0.1 and persists nothing into committed artifacts (gitignored store).
- **The M8 news pillar must not regress.** `news_store.py` is the load-bearing scope risk — its exact-name anchor is consumed by `serve_news` `/anchor`, the live dossier/network view, the 13-fixture replay, and the DuckDB selftests. — Guard: the spine **layers** on the existing store (anchors become one observation type pointing into the new `persistent_entity`) or **extracts a shared pillar-neutral core** leaving `news_store` as a thin pillar-specific adapter; it does NOT rewrite the anchor table out from under M8. `node tests/news-stream.test.mjs` + `python3 tests/news_live_test.py` stay green.
- **Sibling schema drift must fail loud, not mis-resolve.** — Guard: a build-boundary contract test on the consumer side asserts the expected sibling emit shape; versioned schema.

## Success Vision
An investigator opens the second alert on an entity already seen, and the case arrives with its resolved network, source-of-funds state, and prior disposition already attached and grounded — the gather loop visibly short-circuits — while a new, never-seen counterparty honestly shows "we know nothing yet" (not an empty network reading as "no associates"). Two cases firing identical signals still resolve oppositely, and now the *reason* — a strong-identifier-linked network vs. an established legitimate source of funds — is persisted and replayable, with every admitted evidence atom traceable to the graded link that supplied it. The standards read like a contract a sibling team can implement against without a meeting; the briefs name exactly what to emit and why. Nothing the engine decides changed because history accumulated; the file bar is provably the same bar.

## Checkpoints
- After the standards/schemas are drafted (Deliverable 2) and BEFORE building the consumer slice against them: STOP and report the resolution-link schema + the ordinal grade vocabulary — these are the contract everything else depends on; a wrong grade vocabulary propagates into the gate and the briefs.
- After the spine `--selftest` is green and the workbench reads from it but BEFORE the memory demo: report that the matched pair still derives the same verdicts against the live spine (the fixture-drift oracle held).
- If wiring the spine requires ANY change to `evaluate_sufficiency()` or the determination bar: STOP and surface — the file bar is byte-frozen; the confidence path must route around it, not through it.
- If the deterministic linkage cannot separate the matched pair without name-only matching (which the grammar rejects): STOP — the casefile may lack a strong identifier the grammar needs, which is a data-authoring finding, not a license to loosen the grammar.

## Assumptions
- The casefile pair carries strong identifiers (email/phone) sufficient for deterministic linkage of the in-pair entities. If false: the linkage slice is demonstrated on the entities that do carry them and the gap is recorded as a casefile-authoring follow-on — do NOT relax name-only rejection.
- `news_store.py`'s observation/provenance/conflict/prune machinery is genuinely pillar-neutral once the news disposition vocabulary is lifted out. If false: extract the neutral core into a new module and leave `news_store` as a thin pillar-specific adapter over it.
- The "memory" short-circuit can be demonstrated by re-surfacing an entity within the companion (same entity, second case/alert) without needing live model calls. If false: demonstrate deterministically (stub planner) and note the live demonstration as optional.
- Prior dispositions can be attached to entities from an independent-provenance source (a prior case/STR record), not hand-set per case to steer a verdict. If false: scope the memory demo to read-back of a committed prior and flag exogenous-provenance as the substrate brief's job (Deliverable 3b).
- The sibling repos will implement the briefs on their own lifecycles; this phase's success does not depend on their execution. If false (a brief is found infeasible at authoring): record it as an open cross-pillar question, do not block the consumer slice.
