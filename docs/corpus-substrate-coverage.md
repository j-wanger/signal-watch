## 0. Why this exists

The program's detection layer (Pillar 1, aml-substrate) was built **bottom-up**: 6 detectors with
"chosen-not-measured" thresholds authored from individual advisory flags, with **no systematic join to
the corpus catalog** (2,251 indicators / 523 *buildable* = `status=="gap" AND data=="available"`). The
corpus is the program's signal source-of-truth. This map joins the two and answers, per buildable
corpus indicator: **is a grounded signal reachable on the substrate today, and if not, what is the
binding gap?** It converts "build 200+ corpus signals" from an assertion into a measured, itemized,
prioritized build plan — and it is the input to the two sibling build briefs (T3).

## 1. The doctrine boundary (load-bearing — Phase-58 A0)

The corpus drives **detector + observable-exposure** design (top-down — authoring a detector to find a
known typology is normal, not injection). **Data generation and labels stay bottom-up / emergent** —
aml-substrate's doctrine ("typologies EMERGE from modeled behavior, NEVER injected/stamped"). This map
**MEASURES the behavioral-coverage gap; it never stamps it.** The build briefs it produces author
detectors and view-exposure only — **a brief that stamps a behavior or a label is out of bounds.**

## 2. The mapping contract

A corpus indicator becomes a grounded signal on the substrate along this chain:

```
corpus indicator (advisory_id:indicator_id, capability C-code, data_source D-code)
   → the D-code's OBSERVABLE must be available to a detector   [observable-exposure dimension]
   → the C-code's PATTERN must emerge in the generated data    [behavioral-emergence dimension]
   → a detector reads the exposed observable
   → a casework grounding_replay assertion gates it
   → the SAR/STR narrative cites the grounded signal_id
```

Two independent dimensions gate reachability:

- **Observable-exposure (MEASURED).** For each data source D1–D20, `substrate_class(D)` ∈
  `{exposed-active, generated-unexposed, modeled-inactive, not-modeled}`, computed from the substrate's
  schema (the pin, code-verified) **and the real emitted sample** (`data/chain-cases/CASE-P-0010361`,
  71 transactions). It is genuinely measured: D17 (geographic) is `modeled-inactive` *because*
  `counterparty_country` is 0/71 non-null in the actual emission, not by assertion.
- **Behavioral-emergence (REASONED, flagged).** For each capability C1–C28,
  `behavior_emergence(C)` ∈ `{emerges, data-only, absent}`, reasoned from DESIGN.md / the laundering
  engine and carried per-signal. `behavior_confirmed` is `true` only when the capability fires in the
  emission (the 5 detector capabilities) — everything else is honestly flagged reasoned-not-measured.

### The five tiers (the binding gap, hardest-first)

| Tier | Meaning | Fix |
|---|---|---|
| **reachable-now** | a live detector + casework assertion + emergent behavior grounds it | — |
| **needs-detector** | exposed-active observable + behavior emerges, but no detector yet | author a detector + assertion |
| **needs-view-exposure** | the observable is **generated by the substrate but invisible** to the detector views | wire a view |
| **needs-behavior** | exposed but the pattern never emerges (C6 dormancy), or modeled-but-never-populated (D17) | emergence-engine work |
| **out-of-reach** | the data family is not modeled / a dead never-set flag | genuinely unobservable — honest, not a defect |

`reachable-now` carries a **grounding_mode**: `direct` (the detector reads the indicator's own D-code
observable) or `proxy` (the detector grounds via an exposed *transaction* observable substituting an
unexposed/dead D-code — e.g. the shell detector grounds a beneficial-ownership indicator via
transaction throughput, the funnel detector grounds a social-media-solicitation indicator via
transaction fan-out). Proxy grounding is **validated in the emission** (the vendored bundle's 5 alerts
span D2/D13/D3/D8 — two of them proxy).

## 3. The measured findings (corpus@472b44e × substrate@df23bba × casework@2381d71)

**523 buildable corpus indicators.** Reachability on the current substrate:

| Tier | Count | % |
|---|---:|---:|
| reachable-now | 93 | 17.8% |
| needs-detector | 62 | 11.9% |
| needs-view-exposure | 312 | 59.7% |
| needs-behavior | 54 | 10.3% |
| out-of-reach | 2 | 0.4% |

Three findings, each measured:

1. **The detection layer was NOT designed from the corpus — confirmed, sharply.** Of the 5 live
   substrate capabilities {C2, C3, C4, C5, C15}, **only C15 (shell/beneficial-ownership) intersects the
   buildable corpus at all.** C2/C3/C4/C5 (pass-through, funnel, structuring, cash-placement) ground
   **zero** buildable gaps — because those capabilities are mostly `status=="covered"` (the bank already
   has that monitoring), so they are not `gap`, so they are not buildable. All 93 reachable-now signals
   are C15-tagged, and 91 of 93 ground via **transaction-throughput proxy** (the indicator's
   beneficial-ownership data is unexposed). The substrate's detectors were authored against
   already-covered capabilities; they barely touch the corpus's actual gaps. This is the measured proof
   of the phase's premise.

2. **The data is already there — "design the data to support the signals" is mostly EXPOSE, not
   GENERATE.** Only **2 of 523** buildable signals are out-of-reach (both tagged D13 adverse-media, a
   never-set dead flag). The dominant gap is **needs-view-exposure: 312 signals (60%) key on data the
   substrate ALREADY GENERATES but does not expose to the detector views** — there is no Person/Org view
   at all (every KYC/CDD/ownership attribute is generated-but-invisible to detectors), and the channel
   detail tables (MCC, MICR, wire BICs) are likewise unexposed. The single highest-leverage build action
   is **wiring detector views to the rich schema the generator already produces**, not modeling new data.

3. **The path to 200+ is capability-scaled and honest about each gap:**
   - **93** reachable now (1 live shell detector × 93 C15 corpus indicators, mostly via proxy — the
     capability-scaling made concrete).
   - **155** buildable with **detector-work alone** on the current emergent data (93 live + 62 new
     detectors on exposed-active observables — the entire +62 is **C7 peer/business-activity anomaly**,
     emergent via the measured single-feature separability).
   - Exceeding 200 goes **through view-exposure**: the 312 generated-but-unexposed signals each then need
     a screening/behavioral detector (the per-signal `behavior_emergence` carries the secondary gap —
     screening capabilities like C13/C14 need only the exposed state; behavioral ones need the pattern too).
   - **54** need emergence-engine work (behavioral capabilities whose pattern the engine doesn't produce
     — C26 scam, C27 real-estate, C8 income-mismatch on exposed data); **2** are genuinely out-of-reach.

   So 200+ grounded signals is reachable, but the lever ordering is: **expose the KYC/ownership views
   (unlocks the 312) → author the entity/KYC + C7 detectors → grow emergent behavior for the 54.**
   Capability-scaled throughout — NOT 200 detector implementations.

## 5. How this feeds the build (T3 briefs)

The map ranks every capability by signals-unlocked, splitting "wire a detector" (needs-detector, on
already-exposed data) from "expose a view first" (needs-view-exposure). The two sibling briefs consume
that ranking:

- **aml-substrate** (`docs/corpus-coverage-build-PLAN-BRIEF.md`): wire detector views to the generated
  KYC/ownership/PEP schema (the 312 unlock); author the C7 detector (the +62). **Detectors +
  observable-exposure only — no behavior/label stamping** (the doctrine boundary).
- **aml-casework** (`docs/capability-assertions-PLAN-BRIEF.md`): add `grounding_replay` assertions for
  each newly-wired capability (capability-scaled — one assertion grounds many corpus indicators).

The shared acceptance: the coverage map's `reachable-now` count rises as each capability lands
(re-run `--check` against the re-grounded pin).

## 6. Honesty boundaries

- `data_source_class` is **measured** (schema + emission); `behavior_emergence` is **reasoned** from
  DESIGN.md and flagged `behavior_confirmed:false` unless the capability fires in the emission. The
  behavioral tier is a reasoned input to confirm in an aml-substrate-rooted session, never a measured claim.
- `needs-view-exposure` names the **first** binding gap (exposure); behavioral capabilities in that tier
  carry a **secondary** behavior gap (per-signal `behavior_emergence`) — exposing the view is necessary,
  not always sufficient.
- No corpus record, dist, or ship artifact is touched. The map reads the committed corpus and a vendored
  emission; it imports no sibling code (subprocess/file-contract/vendored-pin pattern). build.py never
  imports it.
